# Project context

Before planning a feature or changing application code, read `docs/project-guide.md`
and `.specify/memory/constitution.md`.

For Spec Kit commands, feature selection, or installation changes, read
`docs/spec-kit-guide.md`. Invoke the CLI through `./scripts/specify`.

For the first feature, use `specs/001-online-rooms-chat/spec.md` as the behavior
contract, `plan.md` and `contracts/protocol.md` as the technical design, and
`tasks.md` as the implementation checklist. Keep these artifacts consistent when
requirements change. Mark a task complete only after its stated check passes.

The current deliverable is tooling and specifications. Application files mentioned
in plans and tasks are proposed paths until implementation creates them.
